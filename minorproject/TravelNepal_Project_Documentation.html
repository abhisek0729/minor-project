1. Executive Summary — What is TravelNepal?

TravelNepal is an all-in-one digital tourism ecosystem designed for both tourists exploring Nepal and local tourism businesses (Hotels, Restaurants, Tour Guides).

Unlike standard static travel websites, TravelNepal provides:

  • Autonomous Multi-Agent AI Assistant: A voice-enabled assistant powered by LangGraph and Google Gemini that understands natural speech, plans itineraries, and queries live databases.
  • Verified Database Grounding: Hotel, room, dining, and tour recommendations are linked directly to real database entries with live pricing in NPR and Google Maps integration.
  • Human-In-The-Loop (HITL) Safety: Actions like adding rooms, posting menu dishes, or paying for stays generate interactive proposal cards before altering the database.
  • Role-Based Partner Workspaces: Custom dashboards for Hotel Owners, Restaurant Owners, Tour Guides, and Super Administrators.
  • Voice Expense Ledger: Natural voice logging of trip expenses with automated category breakdowns.
  • Offline 1-Click SOS Panic System: Zero-internet emergency cellular SMS transmission for high-altitude trekking rescue.

3. How the Core Features Work (Step-by-Step)

🤖 A. Autonomous Voice AI & Multi-Agent Assistant

When a user speaks "Find verified hotels in Dharan for 4 guests":

  • Continuous Voice Input: The browser's Web Speech API captures voice with a 3-second silence debounce timer so the user is not cut off mid-speech.
  • Supervisor Routing: FastAPI's LangGraph supervisor classifies the request and routes it to the specialized hotel_search_node.
  • PostgreSQL Querying: Real verified hotel records (e.g. Hotel Pindeshwari, Everest Hotel) are retrieved and returned with /hotels/[id] action URLs.
  • Audio Voice Guide: Natural neural TTS generates audio explaining the amenities.

🛡️ B. Human-In-The-Loop (HITL) Action Proposals

AI does not execute database writes autonomously. When an action is detected:

  • Add Hotel Room (ADD_HOTEL_ROOM): Displays an editable card with Room Number, Category, Price/Night, and photo upload.
  • Add Restaurant Dish (ADD_RESTAURANT_DISH): Displays an editable card with Dish Name, Category dropdown, Price in NPR, and Cloudinary picture upload.
  • Log Expense (LOG_EXPENSE): Displays parsed item name, amount, and category before saving.
  • Booking Confirmation (CREATE_BOOKING): Confirms guests, dates, and amount before redirecting to Khalti.

💼 C. Multi-Role Business Workspaces

  • Hotel Portal (/dashboard/hotels): Room catalog, real-time occupancy, price editing, and reservation logs.
  • Restaurant Portal (/dashboard/restaurant): Digital food menus, dish prices, store OPEN/CLOSED switch, and dining orders.
  • Tour Guide Portal (/dashboard/guide): Trekking tour packages, duration, pricing, and verified license credentials.
  • Admin Portal (/dashboard/admin): Super Admin KYC verification queue, platform metrics, and chronological activity alerts.

💰 D. Voice-Powered Expense Tracker

Saying "Add 20 rupees in expense for a drink":

  • The NLU engine extracts numeric cost (NPR 20) and item name (Drink).
  • Automatically classifies it as Food & Dining and prompts a confirmation card.
  • Aggregates total spent and displays category budget distribution charts.

🚨 E. 1-Click Offline SOS Emergency Protocol (/emergency)

  • 1-Click Panic Button: Acquires device GPS coordinates instantly with one tap.
  • Zero-Internet SMS Relay: In remote mountain regions with no mobile data, it pre-addresses a cellular SMS with live Google Maps coordinates to the Tourist Police (1144) or Nepal Police (100).
  • Hotline Directory: One-tap phone dialers for Flood Rescue (1155), Red Cross Ambulance (102), and Himalayan Mountain Rescue (+977 1-4444555).

4. Presentation & Viva Q&A Guide (FAQ)

Q1: Why did you choose LangGraph instead of a simple single prompt LLM call?
LangGraph allows multi-agent separation of concerns. Instead of one large prompt handling everything, we have specialized sub-agents (Supervisor, Hotel, Restaurant, Itinerary, Expense) that query specific databases and maintain state deterministically.
Q2: How does the system handle hallucinations?
We use database-grounded RAG. Recommendations are fetched directly from our PostgreSQL database with real IDs and verified listings, ensuring links and pricing are 100% accurate.
Q3: How does the SOS system operate without internet?
It uses the browser Geolocation API offline to obtain device GPS coordinates and triggers the native sms: protocol with pre-formatted coordinates addressed to Tourist Police (1144) over standard cellular GSM networks.
Q4: How are payments handled safely?
We integrate Khalti and eSewa digital wallet gateways. Bookings are initialized in a pending state and only marked confirmed after server-side cryptographic transaction verification.
